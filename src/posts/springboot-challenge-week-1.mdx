## JVM이란 무엇이고, Java가 어떻게 여러 OS에서 동작하나요?
     - JVM은 Java Virtual Machine으로 바이트 코드에서 기계어로 실제 컴퓨터가 이해할 수 있게 도와준다.
     - java는 코드를 컴파일하면 바이트 코드로 저장된다. 이 바이트 코드는 어떤 os든간에 JVM이 설치만 되어있으면 작동한다
## 객체지향의 4대 특징(캡슐화·상속·다형성·추상화)을 각각 예시와 함께 설명해주세요
     - 캡슐화: 데이터를 잠궈 아무곳에서나 접근을 못하게 막는다
     ```java
            public class BankAccount {
                private int balance;

                public void deposit(int amount) {
                    if (amount > 0) balance += amount;
                }

                public void withdraw(int amount) {
                    if (amount <= balance) balance -= amount;
                }

                public int getBalance() { return balance; }
            }           
     ```
     - 상속: 공통된 부분을 부모 클래스로 올리고 자식이 물려받는다
     ```java
            public class Animal {
                public void eat() { System.out.println("밥을 먹는다."); }
            }

            public class Dog extends Animal {
                public void fetch() { System.out.println("공을 물어온다."); }
            }
     ```
     - 다형성: 같은 타입으로 다루더라도, 실제 객체에 따라 다른 동작을 한다.
     ```java
            public interface Payment {
                void pay(int amount);
            }

            public class CardPayment implements Payment {
                @Override
                public void pay(int amount) { System.out.println("카드로 " + amount + "원 결제"); }
            }

            public class KakaoPay implements Payment {
                @Override
                public void pay(int amount) { System.out.println("카카오페이로 " + amount + "원 결제"); }
            }
     ```
     - 추상화: 불필요한 세부 구현은 숨기고, 핵심 기능만 드러낸다.
     ```java
            public interface Payment {
                void pay(int amount);
            }

            public class CardPayment implements Payment {
                public void pay(int amount) { System.out.println("카드로 " + amount + "원 결제"); }
            }

            public class KakaoPay implements Payment {
                public void pay(int amount) { System.out.println("카카오페이로 " + amount + "원 결제"); }
            }
     ```

## 인터페이스는 왜 필요한가요? 오늘 실습에서 PostRepository를 인터페이스로 만든 이유를 코드로 설명해주세요
    인터페이스는 무슨 기능들이 있는지만 하고 어떻게 할지는 정하지 않아서, 구현을 바꿔도 사용하는 쪽에 코드는 수정을 안해도 된다.
    ```java
        // 약속
        public interface PostRepository {
            Post save(Post post);
        }
        
        // 구현
        public class MemoryPostRepository implements PostRepository {
            private final Map<Long, Post> store = new HashMap<>();
        
            @Override
            public Post save(Post post) {
                store.put(post.getId(), post);
                return post;
            }
        }
        
        // 사용: Service는 인터페이스만 앎
        public class PostService {
            private final PostRepository postRepository;
        
            public PostService(PostRepository postRepository) {
                this.postRepository = postRepository;
            }
        }
        
        // Main: 여기만 바꾸면 저장 방식 교체
        new PostService(new MemoryPostRepository());
    ```
